# AgentChat 接收整合

本版自動接收本機 Codex、Claude Code、OpenCode 與 Claude Desktop 已知快取格式的聊天內容，並保留 MCP 提問、回答與附件。AgentChat 不發送新任務，不修改客戶端登入設定。
更新後重新啟動 AgentDock 即啟動接收器；重新連接 MCP 可載入新的工具指引，不用重裝。尚未更名的舊 `agentdock-qa`／`agentdock_qa` 可另從設定頁「全部更新」預覽、確認及備份遷移為 `agentchat`。

## 自動接收

聊天通知採浮動小圖示紅點：有待回覆或未讀時顯示，全部讀取／回答／取消後消失。不跳聊天系統通知、不自動展開面板；一般程式錯誤及設定操作提示不受影響。

Codex 的結構化 `local_image` 區塊另支援本機圖片路徑：讀取後保存附件副本，略過網路共享路徑，沿用大小限制。對應的 Files mentioned／My request 包裝只在含圖片附件標記時整理成實際輸入；不從一般訊息文字提取檔案路徑。此修正適用於更新後新接收的訊息，不回放舊訊息。

圖片：MCP 問題與已提交回答的圖片可在聊天泡泡查看縮圖並點擊放大。原生紀錄中的明確圖片區塊若附有 base64 圖片資料也可顯示，並保存到本機附件目錄；每則最多 8 張、單張 5 MB、總量 20 MB。只有路徑／網址、超限或格式不支援時顯示「圖片無法取得」，不自動下載外部圖片。先前已略過的歷史圖片不補匯入。Claude Desktop 支援明確 image 區塊的 source.base64／file.base64；空內容、遠端網址或未快取圖片顯示缺圖提示，不下載私人資源。

每次啟動 AgentDock，清單只顯示本次收到新訊息的對話；未回答的問題保留。切換分頁或收起面板不重設。已儲存歷史不刪除，對話有新活動時可一起查看。Codex／OpenCode 的封存或移除仍會隱藏一般對話；解除封存本身不算新訊息。來源讀取失敗保留上次結果。Claude Code 尚無已核實封存欄位，只能依紀錄檔存在與否判斷。這些動作不取消或代答問題。

- Codex：預設讀取 `CODEX_HOME` 或 `~/.codex`，以及設定頁已登錄的 Codex 設定檔旁的資料。從任務索引取得真正名稱與對話 ID，從 JSONL 取得原始文字與開始／完成事件。
- Claude Code：預設讀取 `CLAUDE_CONFIG_DIR` 或 `~/.claude`，以及已登錄設定檔旁的 `projects`。使用 custom-title／ai-title；尚未有標題才以第一則輸入暫代。
- OpenCode：唯讀讀取 `XDG_DATA_HOME/opencode` 或 `~/.local/share/opencode` 的 `opencode.db`，以 session/message/part 取得主對話。這條路不要求啟動額外 HTTP Server，也不讀取憑證。
- Claude Desktop 一般 Chat：讀取一般安裝／Microsoft Store／登錄設定旁的 IndexedDB，解析 claude-conversation-store 的 Hub、舊 Chat 選定分支與 Cowork 事件。以暫存快照唯讀解析、最高 sequence 去重並排除 tombstone；快取缺失不隱藏既有歷史。標題以第一則可用使用者文字暫代。新版統一介面依格式辨識；Claude Code 原生 JSONL 沿用既有接收器。獨立 Code 介面無本機樣本，背景對話完整性仍未保證。問答以已登錄 caller 的工具參數或實際結果 ID 合併，不改問題 owner 或代答。
- 原生訊息以對話 ID 與訊息 ID 去重，保留時間；串流更新同一則泡泡。工具輸出、思考、內部提示、子代理對話不顯示；原生附件目前不複製，MCP 問答附件仍完整保留。
- 背景每 2 秒檢查本機檔案變更，未變不重讀內容、不重建面板。略過啟動前及關閉期間的訊息，不補入舊任務；啟動後的新完成事件依通知開關通知。OpenCode 以訊息及文字片段更新時間判斷，因此啟動前開始、啟動後完成的回覆仍會接收。
- 讀取進度存於 `chat-sync.json`；JSONL 寫到一半會等完整行才讀。資料庫均以唯讀模式開啟。這些是客戶端內部格式，版本變更可能需要更新接收器；讀取錯誤可由「自動接收／接收需檢查」提示查看。

## 問答如何連回原對話

包含 Desktop 在內，接收器解析實際 ask_user 呼叫的固定 work_id/request_key，或其真實 MCP 結果 ID，將問答顯示在原生對話。協定 owner、request_id 與回答內容不改寫。以程式變數動態組合參數且無法解析時，要等工具結果留下 ID 才能連結；不依標題或文字猜配。

## Agent 使用方式

- 同一個任務固定使用 `work_id`，能取得原生 session ID 時直接使用。不同任務即使使用同一 Agent 也必須用不同 ID。
- 支援自動接收的客戶端不再使用 `report_to_user` 複製聊天。下述回報方式僅供未支援的客戶端或使用者明確要求的獨立回報。
- 備援回報的 `user_message` 只放使用者實際原文；`started` 表示開始，不捏造使用者訊息。
- 需要回答時使用既有 `ask_user`；使用者取消或工具逾時不代表同意。逾時保留 request_id，以 `get_user_answer` 恢復等待。
- 任務完成呼叫 `report_to_user`，kind 為 `completed`，text 放最終結果。失敗用 `failed`，已結束的取消用 `cancelled`；仍有可見待答問題時會拒絕結束回報。
- 備援 completed 的 text 應與原聊天的最終回覆逐字一致，不另寫摘要。支援的客戶端直接讀取原始紀錄，不靠此指引維持一致。
- 完成／失敗／取消回報會發出 Windows 通知，面板展開時也通知；由右鍵「問題與任務回報通知」控制，實際顯示仍受 Windows 通知設定影響。
- `progress` 僅用於重要進度，保持原任務狀態；不用持續回報心跳。
- 每個事件使用不同 `request_key`；重試同一事件用原 key。相同 key 不同內容會報錯，回報立即返回，不等待使用者。

範例參數：

```json
{
  "request_key": "run-42-completed",
  "work_id": "conversation-123",
  "work_title": "登入頁調整",
  "kind": "completed",
  "text": "已完成登入頁調整，測試通過。"
}
```

## 顯示與保留

列表先顯示最近 60 個任務，可按「載入更多對話」。每次開啟對話先顯示最近 30 筆紀錄，透過「較早訊息／較新訊息／最新訊息」瀏覽；歷史不刪除。超過 3000 字的訊息先顯示預覽，按「查看全文」可讀取及複製完整原文。更新只修改有變動的泡泡，不反覆重建整頁；閱讀較早頁面時保持所在位置。

打開對話或按「最新訊息」會直接置底。若停在底部，新回覆也會跟著往下；手動往上捲或切到較早頁面後，不會被新訊息拉回底部。

列表以 Agent 為分組標題，各個任務縮排在下方。點入任務後，Agent 問題與回報顯示在左側泡泡，你的同步指令及回答顯示在右側；回答依實際提交時間排列。從泡泡進入回答表單，送出後返回原對話。

待答問題顯示「待回覆」；開始事件或回答後顯示「進行中」；完成、失敗或取消結果尚未閱讀時顯示「未讀取」。泡泡只顯示內容與時間，以左右位置區分雙方，不另標稱謂或訊息類型。同步的使用者訊息仍是在原客戶端輸入，不代表是在 AgentChat 發出的。

歷史與已讀狀態保存在本機；重開只重設顯示清單。「進行中」不跨啟動推定；待答問題仍顯示並提示等待連線。提問泡泡只顯示問題，回答泡泡只條列已選選項；自由文字、備註與附件均保留於詳細頁。點「查看問答與附件」進入原有附件／選項／草稿編輯器，再以「對話歷史」回去；無選項的回答只保留時間與詳細頁入口。

移除對話不取消 Agent 任務。事件從顯示歷史移除，問題僅隱藏，內部問答資料及附件仍保留供 caller 取回答案與重試；這不是永久刪除所有資料。後續新事件會重新建立區域，明確重試 ask_user 可恢復原問題。

## 接收一致性邊界

各來源共用問答、圖片縮圖、缺圖提示、未讀及焦點規則。已知工具中途說明隱藏，未能分類的進度不擅自丟棄。完成時間決定未讀／列表更新，訊息仍保留原始建立時間。Desktop 快取淘汰不等同刪除；原生封存同步、完整歷史及圖片可取得性仍受來源提供的資料限制。

Desktop 的 files_v2 圖片附件會查找本機 HTTP 快取（Windows blockfile／Simple Cache v9）。找不到內容時顯示「圖片無法取得」，不會靜默略過附件，也不透過網路下載。快取稍後更新可補圖；已保存圖片不因来源快取清除而消失。接收不需要求 Claude 使用 MCP。
